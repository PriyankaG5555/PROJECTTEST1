# Frontend Spec — Trip Planner (GhumakkadYatri)

> Purpose: Define the UI, user flows, and client-side architecture. Must satisfy user stories in `goal-spec.md` and consume only endpoints defined in `api-contract-spec.md`.

## 1. Tech Stack
- **Framework:** React 18 (single-page app)
- **Language:** TypeScript
- **Styling:** Tailwind CSS (mobile-first utility classes)
- **State management:** TanStack Query for server data; React state/context for UI-only state (current user, open dialogs)
- **Data fetching:** `fetch` wrapper (`api/client.ts`) + TanStack Query hooks; cookies sent with `credentials: "include"`
- **Routing:** React Router v6
- **Forms & validation:** React Hook Form + Zod
- **Build tool / package manager:** Vite + npm
- **Testing:** Vitest + React Testing Library (unit/component); Playwright (e2e for P0 flows)

## 3. User Flows
### Flow 1: Sign up / Log in
1. User opens app → redirected to `/login`.
2. New user clicks "Create account" → `/signup` → submits username + password.
3. On success the user is logged in and sent to `/trips`.
4. Returning user logs in on any device → `/trips` shows the same trips (data comes from the server).

### Flow 2: Create and plan a trip
1. On `/trips`, user clicks **New trip** → `/trips/new`.
2. User enters destination, start date, end date, trip type → **Create**.
3. App navigates to `/trips/:tripId`. The trip is **Draft** with one draft named "Draft 1", pre-split into Day 1 … Day N.
4. In each day, user clicks **Add activity** → enters destination name (required), time, cost, priority → **Save**.
5. Activities in a day are listed by start time; activities without a time appear last. Day and trip cost totals update.

### Flow 3: Multiple drafts (P1)
1. In the planner, user opens the **draft switcher** → **New draft** → chooses "Blank" or "Copy of <draft>" and gives it a name.
2. User switches between drafts from the switcher; each draft has its own activities.
3. User can rename or delete a draft (the last remaining draft cannot be deleted).

### Flow 4: Compare drafts (P2)
1. From the planner, user clicks **Compare drafts** → `/trips/:tripId/compare`.
2. User selects Draft A and Draft B → page shows both side by side, day by day, with total cost per day and per trip.
3. User can click **Use this draft** on one side → returns to the planner with that draft selected.

### Flow 5: Finalize, export, reopen
1. In the planner (Draft trip), user clicks **Finalize** on the selected draft → confirmation dialog → trip becomes **Finalized**.
2. A Finalized trip is read-only: add/edit/delete controls are hidden; **Export PDF** and **Reopen for editing** are shown. The finalized draft is marked "Final" in the draft switcher; the other drafts are **kept, read-only**, and can still be viewed and compared.
3. **Export PDF** downloads the itinerary PDF (generated by the backend).
4. **Reopen for editing** → confirmation → trip returns to **Draft** and editing is enabled again. Export is hidden until the trip is finalized again.

### Flow 6: Edit / delete trip (P1)
1. From My Trips or the planner, user chooses **Edit trip** → `/trips/:tripId/edit` → saves changes.
2. If the new dates shorten the trip and days with activities would be removed, a warning lists the affected days and activities (in every draft). On confirmation those activities are **deleted**; on cancel nothing changes.
3. **Delete trip** → confirmation dialog → trip removed → back to `/trips`.

## 5. State & Data Model (Client)
- **Server state (TanStack Query):** current user, trips list, trip detail, drafts with days and activities. Query keys: `["me"]`, `["trips"]`, `["trip", tripId]`, `["draft", draftId]`.
- **After any change** (create/edit/delete, finalize, reopen), the related queries are invalidated so the UI refreshes from the server.
- **UI state:** selected draft ID (kept in the URL query `?draft=<id>` so it survives reload), open dialogs.
- **No trip data is stored in localStorage**; the server is the single source of truth (supports multi-device use, G2).

Key client-side types (must match `api-contract-spec.md`):
```ts
type TripType = "solo" | "couple" | "family" | "friends";
type TripStatus = "draft" | "finalized";
type Priority = "high" | "medium" | "low";

interface Trip {
  id: string;
  destination: string;
  startDate: string;          // YYYY-MM-DD
  endDate: string;            // YYYY-MM-DD
  tripType: TripType;
  status: TripStatus;
  finalizedDraftId: string | null;
  createdAt: string;
  updatedAt: string;
}

interface Draft {
  id: string;
  tripId: string;
  name: string;
  days: Day[];
  totalCost: number;          // INR
}

interface Day {
  dayNumber: number;          // 1..N
  date: string;               // YYYY-MM-DD
  activities: Activity[];
  totalCost: number;          // INR
}

interface Activity {
  id: string;
  destinationName: string;    // required
  time: string | null;        // "HH:mm" 24h
  cost: number | null;        // INR
  priority: Priority | null;
}
```

## 6. API Integration
> Endpoint paths are provisional; the final paths are defined in `api-contract-spec.md`.

| UI action | Endpoint (from API contract) | Loading / error handling |
|-----------|------------------------------|--------------------------|
| Sign up | `POST /auth/signup` | Button spinner; show "username taken" / validation errors inline |
| Log in | `POST /auth/login` | Button spinner; "Invalid username or password" |
| Log out | `POST /auth/logout` | Clear query cache, go to `/login` |
| Load current user | `GET /auth/me` | On 401 → redirect to `/login` |
| List trips | `GET /trips` | Skeleton cards; EmptyState "No trips yet"; ErrorState with retry |
| Create trip | `POST /trips` | Button spinner; field errors inline |
| Get trip | `GET /trips/:tripId` | Page spinner; 404 → Not Found |
| Edit trip | `PATCH /trips/:tripId` | Inline errors; warning if days with activities would be removed |
| Delete trip | `DELETE /trips/:tripId` | Confirm first; toast on success |
| List / get drafts | `GET /trips/:tripId/drafts`, `GET /drafts/:draftId` | Spinner in planner area |
| Create / rename / delete draft | `POST /trips/:tripId/drafts`, `PATCH /drafts/:draftId`, `DELETE /drafts/:draftId` | Toast on success/failure |
| Add / edit / delete activity | `POST /drafts/:draftId/activities`, `PATCH /activities/:id`, `DELETE /activities/:id` | Optimistic update; roll back and show toast on error |
| Finalize trip | `POST /trips/:tripId/finalize` (body: `draftId`) | Confirm first; refresh trip |
| Reopen trip | `POST /trips/:tripId/reopen` | Confirm first; refresh trip |
| Export PDF | `GET /trips/:tripId/export.pdf` | Button spinner; download file; 409 (trip not finalized) → toast |

Global rules:
- Any **401** → clear cache, redirect to `/login?next=<current path>`.
- **409** for edits on a Finalized trip → toast "This trip is finalized. Reopen it to edit." and refresh.
- Network errors → toast with "Retry".

## 7. Forms & Validation
| Form | Fields | Validation rules |
|------|--------|------------------|
| Sign Up | username, password, confirm password | Username 3–30 chars, letters/numbers/underscore; password ≥ 8 chars; confirm must match |
| Log In | username, password | Both required |
| Trip (create/edit) | destination, startDate, endDate, tripType | Destination required, ≤ 100 chars; dates required; endDate ≥ startDate; trip length 1–30 days; tripType one of solo/couple/family/friends |
| Activity | destinationName, time, cost, priority | destinationName required, ≤ 100 chars; time optional, valid `HH:mm`; cost optional, number ≥ 0 with up to 2 decimals; priority optional, high/medium/low |
| Draft | name | Required, ≤ 50 chars, unique within the trip |

Client-side validation is for user feedback only; the backend validates everything again.

## 8. UI / UX Guidelines
- **Brand:** GhumakkadYatri — Gen Z, friendly, adventurous.
  - **Logo:** [`assets/logo.svg`](assets/logo.svg) — a Gen Z traveller (bucket hat, sunglasses, hoodie, sneakers) with a backpack, waving, on a light-blue circle; wordmark "Ghumakkad**Yatri**" with tagline "PLAN · PACK · GO". The icon part alone is used as the favicon and on small screens.
  - **Primary colour: light blue** (Tailwind `sky` palette):

    | Token | Hex | Use |
    |-------|-----|-----|
    | `brand-50` | `#F0F9FF` | Page background |
    | `brand-200` | `#BAE6FD` | Cards, highlights, selected day |
    | `brand-400` | `#38BDF8` | Borders, icons, decorative accents |
    | `brand-500` | `#0EA5E9` | Logo accent |
    | `brand-700` | `#0369A1` | Primary buttons (white text), headings, links |
    | `brand-900` | `#0C4A6E` | Body text on light blue |
    | `accent` | `#FB923C` | Backpack orange — sparing highlights |

    Light blue (`brand-200/400`) is for backgrounds and decoration only; text and buttons use `brand-700` or darker so contrast stays ≥ 4.5:1.
  - **Fonts** (Google Fonts): **Poppins** (600/700) for headings, logo and buttons — rounded and playful; **Inter** (400/500) for body text, forms and tables — very readable on mobile.
- **Design system / theme:** Tailwind with the brand tokens above and a small set of shared components. Status colors: Draft = amber, Finalized = green. Priority colors: High = red, Medium = amber, Low = grey (always with a text label, not color alone). Rounded corners (`rounded-xl`), soft shadows.
- **Responsiveness:** Mobile-first. Breakpoints: < 640px (phone): one day per row, stacked; 640–1024px (tablet): two columns; > 1024px (laptop): planner shows days in a scrollable grid. Compare page stacks Draft A above Draft B on phones.
- **Accessibility:** WCAG 2.1 AA: labelled form fields, keyboard navigation for all actions, visible focus, colour contrast ≥ 4.5:1, dialogs trap focus and close with Esc.
- **Empty / loading / error states:** Every list has an empty state (e.g. "No activities yet — add one"); loading uses skeletons/spinners; errors show a message and a Retry button.
- **Currency & dates:** Costs shown as INR with `₹` and Indian digit grouping (`Intl.NumberFormat("en-IN", { style: "currency", currency: "INR" })`). Dates shown as `Sat, 4 Oct 2026`.

## 9. Authentication (Client side)
- Backend sets an **httpOnly, Secure, SameSite cookie** on login/signup; the frontend never reads or stores the token (no localStorage).
- On app load, `GET /auth/me` decides whether the user is logged in.
- `ProtectedRoute` wraps all `/trips/*` routes; unauthenticated users go to `/login?next=…` and return there after login.
- **Log out** calls `POST /auth/logout`, clears the TanStack Query cache, and navigates to `/login`.
- Logged-in users visiting `/login` or `/signup` are redirected to `/trips`.

## 10. Non-Functional Requirements
- **Performance:** First load < 3s on a 4G connection; route-level code splitting; JS bundle < 300 KB gzipped.
- **Browser support:** Latest 2 versions of Chrome, Edge, Firefox, Safari (desktop and mobile).
- **i18n / localization:** English only in MVP; INR currency and Indian number formatting. Text kept in one place so translations can be added later.
